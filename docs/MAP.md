# Map layers, navigator and gathering nodes

Claude can mark your world map. What it draws are **layers**: a named list of points (`uiMapID`, x, y in map percent, a label, a kind), optionally **ordered** (a route: numbered pins joined by lines) and **looping** (a farming circuit).

## How marks get from Claude to the game

1. For every run the bridge sets `WOWCLAUDE_MAP_FILE` to a fresh file in `bridge/mapjobs/`. Tools append commands there, one JSON object per line:

   ```json
   {"op":"set","layer":"mining","title":"Copper loop","ordered":true,"loop":true,"points":[{"m":1432,"x":41.5,"y":47.8,"label":"1. Copper Vein","kind":"ore"}]}
   {"op":"clear","layer":"mining"}
   {"op":"clearall"}
   ```

   Claude can also put a few marks in its reply inside a ```` ```wowmap ```` block; the bridge takes the block out of the text.
2. When the run ends the bridge validates the commands (`protocol.js`: sanitized labels, coordinates clamped to 0-100, at most 400 points per layer, 1500 in total, 12 layers with the oldest dropped first), applies them to the layers it keeps in `state.json`, and bumps a version number. The reply gets a `[map] ...` line saying what changed.
3. The next slot files carry the whole set (`map = { epoch, version, layers }`) for ten minutes, and again after every hello. The addon replaces its copy when the version is newer (or the bridge's state was reset). A mark can't be applied twice, and a client that lost its saved data gets the layers back when it says hello.

## In game

- **World map:** pins for every visible layer on the map you are looking at, projected onto continent maps too. Hover for the label; click a pin to navigate to it.
- **Navigator:** a small frame with an arrow and the distance in yards to the current stop of the route. It starts on a route as soon as one arrives, advances when you get within 12 yards, and wraps around on loops. Drag it to move it; right-click skips a stop. It shows "no position here" in instances, where the game gives addons no coordinates.
- **Herb and ore nodes:** with the `WoWClaude_Nodes` data addon installed (generated by the copilot's `npm run build -- --addons ...`), every herb and ore spawn point of the zone on the world map, filtered to what your skill can gather.

| Command | Does |
|---|---|
| `/wcmap` | List layers, navigation and node settings |
| `/wcmap ore [on\|off]`, `/wcmap herb [on\|off]` | Show or hide mining / herbalism nodes |
| `/wcmap filter all\|skill` | Every node, or only those your skill can gather (default) |
| `/wcmap hide <layer>`, `/wcmap show <layer>` | Hide or show a layer locally |
| `/wcmap nav <layer> [n]`, `next`, `prev`, `stop` | Drive the navigator |

Everything here only reads positions and draws. Nothing moves, targets or acts for you.

## The copilot

`wow-copilot` is a companion data folder meant to be the bridge's working folder (`node setup.js --project ~/projects/wow-copilot`, or start the bridge from it). It builds JSON datasets from QuestieDB (Forever), AtlasLootClassic and the vmangos DB (quests, NPCs, objects, items, every herb and ore spawn, recipes with trainers and sources, dungeons, zone geometry), and gives Claude a CLI to query them and to build routes (nearest neighbour + 2-opt on real yard distances; quest routes keep pickup, objectives and turn-in in order). Its `CLAUDE.md` tells Claude how to use the game context the addon sends (position, level, professions, quest log) and how to draw on the map.
